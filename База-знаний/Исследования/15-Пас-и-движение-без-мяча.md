# 15. Пас и движение без мяча

**Зачем этот документ.** Пас — это ядро игровой петли PES, и он у нас сейчас проигрывает дриблингу арифметически, а не «на ощущение». Ниже — числа, по которым пас становится выгоднее, чем везти мяч ногами: модель оценки опций, ошибка исполнения, приём, таксономия рывков без мяча с триггерами, комбинации и расстановка. Все константы предполагаются в `src/config.js`, ролевые таблицы — в `data/`.

Термины: **xT** (expected threat, ожидаемая угроза) — вероятность, что владение из данной точки поля закончится голом. **Pitch control** — вероятность, что мячом в данной точке овладеет твоя команда. **Cutback / прострел** — низкая передача назад от лицевой линии в зону перед воротами. **Overlap / underlap** — забегание снаружи / изнутри от партнёра с мячом.

## 1. Арифметика скоростей: почему дриблинг сейчас побеждает

Наше качение мяча (`src/ball.js`) — экспоненциальное затухание скорости, `rollFriction = 0.988` за кадр при 60 fps. Это значит:

```
λ = −60 · ln(0.988) = 0.724 с⁻¹        // коэффициент затухания качения
v(d)  = v0 − λ·d                        // скорость мяча, прокатившегося d метров
d_max = v0 / λ                          // полная дальность наката
t(d)  = −(1/λ) · ln(1 − λ·d / v0)       // время прихода мяча на дистанцию d
```

Это точные выражения, а не приближения — они следуют из `dv/dt = −λv`.

**Проверка физики нормативом FIFA.** Стандарт ISSS/DIN 18035-7 катит мяч с рампы: реальная скорость схода сертифицированных мячей — **3.20 м/с**, норматив дистанции наката — **4.0–8.0 м**. Наша модель даёт `d_max = 3.2 / 0.724 = 4.42 м` — попадает в норматив по нижнему краю (поле «быстрое», как и должно быть у подстриженного газона телетрансляции). Физику качения трогать не нужно.

**А вот сила паса сломана.** `src/ai/team.js:629` считает `v0 = clamp(d·0.55 + 5.5, 11, 24)`:

| d, м | v0, м/с | d_max | v на приходе | t полёта | спринт (9.18 м/с) покроет d за |
|---|---|---|---|---|---|
| 10 | 11.0 | 15.2 м | 3.8 м/с | 1.44 с | 1.09 с |
| 15 | 13.75 | 19.0 м | 2.9 м/с | **2.15 с** | 1.63 с |
| 24 | 18.7 | 25.8 м | 1.3 м/с | **3.65 с** | 2.61 с |

**Пас по земле сейчас медленнее, чем везти мяч спринтом, на всех дистанциях.** Это и есть корневая причина, по которой во всех футбольных играх дриблинг доминирует: у Бакленда безопасность паса считается как `reach = скорость_соперника · время_полёта` — чем дольше летит мяч, тем шире конус перехвата. Никакая модель оценки паса не спасёт, пока это не исправлено.

**Правка (обязательна перед всем остальным):** задавать не начальную, а **приходящую** скорость.

```js
passArriveSoft:   6,    // скидка в ноги стоящему
passArriveNormal: 9,    // обычный пас
passArriveDriven: 13,   // прострельный, под давлением
// v0 = arrive + λ·d,  λ = 0.724
```
d = 15 → v0 = 19.9 м/с, t = 1.09 с, средняя скорость 13.8 м/с = **1.5× спринта**. d = 24 → v0 = 26.4, t = 1.64 с. `passSpeedMax` поднять до 30, `passSpeedMin` до 12.

**Побочное правило (Operation Sports, тюнинг слайдеров FIFA):** скорость паса и рискованность AI — одна система. Снижение скорости паса без ретюна модели риска превращает AI в бесконечное тики-така. Эту правку и веса из §4 катить одним коммитом.

**Справочная физика мяча** (если понадобится честный полёт): масса **0.43 кг** (Jabulani 0.438, Tango 12 0.428 — не 0.45, это верхняя граница Правил), площадь 0.038 м², ρ = 1.22, `k = ρ·Cd·A/(2m) = 0.0138 м⁻¹`, торможение в воздухе `= k·v²`. Cd реально меняется втрое: докритический (медленный мяч, навес) **0.44–0.47**, сверхкритический (сильный удар) **0.15–0.22**, переход на ~19 м/с. Одна константа 0.25 занижает торможение навеса вдвое — если хотим «навес висит, а прострел летит», Cd нужен двухступенчатый.

## 2. Таксономия передач: четыре оси вместо тридцати кнопок

У EA FC 25/26 — 29 приёмов паса, но собраны они комбинаторно из 3 кнопок × 4 модификаторов. Читая их насквозь, пространство сворачивается в **4 ортогональные шкалы** плюс 2 «цены»:

| Ось | Диапазон | Что делает |
|---|---|---|
| **Высота вылета** | земля → «выше колена» → навес → высокий навес | обход соперника по вертикали |
| **Скорость vs дуга** | driven (настильно+быстро) ↔ lob (медленно+высоко) | «драйвовый навес» = меньше высоты, быстрее |
| **Упреждение (lead)** | в ноги (0 м) → на ход (2–8 м перед) | у EA полоска силы на precision through ball задаёт **метры упреждения**, а не скорость |
| **Подкрутка** | 0 → максимум | у EA включается выше порога силы, масштабируется атрибутом Curve |
| *цена 1* | вероятность перехвата | у настильного ниже |
| *цена 2* | сложность приёма | верховой и «выше колена» — «игроку нужно дольше, чтобы обработать» |

Из этого — наш минимальный набор семейств (совместим с ретро-схемой PES 6, где высота навеса задавалась числом тапов ○):

1. **Пас по земле** — `arrive = 9`, ошибка ×1.0, приём ×1.00
2. **Настильный / прострельный** — `arrive = 13`, ошибка ×1.0, приём ×0.90
3. **Пас на ход (through)** — цель вынесена вперёд, ошибка ×1.2, приём ×1.15 (адресат не теряет скорость)
4. **Верховой адресный** — ошибка ×1.4, приём ×0.78
5. **Навес в штрафную** — ошибка ×1.4, приём ×0.78
6. **Cutback / низкий прострел** — по земле от лицевой, ошибка ×1.0, приём ×1.00

**Ключевое замечание про полоску силы:** она должна означать **разное для разных семейств**. Для обычного паса — скорость; для паса на ход — **метры упреждения**; для навеса — высоту дуги. Это единственный числовой порог, который EA вообще опубликовала (подкрутка включается «выше двух делений»), и он работает как принцип.

**Оба контринтуитивных урока из PES-сообщества, которые надо запомнить:**
- Полностью ручной пас — ошибка. Ассист нужен для того, **чтобы статы игрока могли себя проявить**; при полном мануале всё решает рука игрока, и индивидуальность стирается. Скилл-гэп создаётся выбором адресата, весом паса, таймингом и движением без мяча — не отсутствием ассиста.
- Ассист должен быть **числом (`assist ∈ 0.0…1.0` = доля применяемой коррекции)**, а не флагом. Модеры PES искали «PA 0.5» именно потому, что бинарного переключателя мало.
- **Асимметрия PES, лучшая идея во всём ресёрче:** ассистированный пас проверяется на автоперехват защитой, ручной — не проверяется. Бесплатный размен риск/награда, ноль нового UI.

## 3. Оценка опций паса

### 3.1 Генерация кандидатов

На каждого партнёра `R` — до 5 целевых точек, каждая в 1–2 вариантах высоты:

1. **В ноги с упреждением:** `T = R + v_R · t · 0.8`
2. **На ход:** `T = R + û_R · (v_R·t·1.5 + 2.0)` — фикс +2 м, чтобы мяч ложился ПЕРЕД, а не в пятки
3–4. **Две касательные** к кругу перехвата адресата радиусом `r = Vспринт · t · 0.30`. Коэффициент 0.30 — прямо из `GetBestPassToReceiver` Бакленда: «получатель реально использует лишь 30 % теоретического радиуса». Это даёт пас «в сторону от опекуна», а не в корпус.
5. **В зазор (passing lane):** если между двумя соперниками щель ≥ 4.0 м и адресат туда успевает — точка в середине щели. Это ровно то, что FC 26 назвал «aiming at a specific passing lane… respecting your aim and intention».

`t` решается двумя итерациями фиксированной точки: `t0 = t(|R−B|)` → пересчёт цели → `t1 = t(|T−B|)`. Дальше не итерируем, ошибка < 4 %.

Отсев до скоринга: `4.5 ≤ d ≤ 36`, цель внутри поля с запасом 1.5 м, `v0 ≤ 30`.
Бюджет: 10 партнёров × 5 × ~1.4 ≈ **70 кандидатов на такт решений 0.28 с** — на 60 fps дёшево.

### 3.2 Перехват — модель ВРЕМЕНИ, а не коридора

Для линии `B → T` длиной `D` и каждого из 4 ближайших к линии соперников:

```
локальные координаты: a — вдоль линии, b — поперёк
если a < 0                → соперник позади пасующего, пропускаем
a_c = clamp(a, 0, D)
t_ball = t(a_c)                                   // формула §1

s = max(0, |b| − 0.9)                             // 0.9 м — ширина корпуса
t_move = (s < 9.4) ? sqrt(2s / 4.5)                // разгон 4.5 м/с² из покоя
                   : 9.18/9 + s/9.18              // затем крейсер
t_opp  = 0.35 + t_move                            // 0.35 с — реакция
margin = t_opp − t_ball
p_int  = 1 / (1 + exp(4.03 · margin))
```

Коэффициент **4.03 = π/(√3·σ)** при **σ = 0.45 с**. Это не «чужой дефолт»: σ = 0.45 ± 0.01 — результат подгонки максимального правдоподобия по **10 875 реальным пасам АПЛ** (38 матчей, трекинг 25 к/с). Та же σ обслуживает модель прессинга (§6) — в конфиге это ОДНА константа.

| margin, с | −0.3 | −0.15 | 0 | +0.15 | +0.3 | +0.5 |
|---|---|---|---|---|---|---|
| p_int | 0.77 | 0.65 | 0.50 | 0.35 | 0.23 | 0.12 |

```
P_complete = Π (1 − p_int_j)
если |b| < 1.0 и 0 < a < D  →  P_complete = 0        // соперник физически на линии
если пасующий под прессингом →  margin += 0.18 с      // «деваться некуда, отдавай»
```

**Что это чинит.** Текущий конфиг режет скорость соперника коэффициентом `speedK = 0.55`, потому что «плоская» модель в метрах не знает, что защитник разгоняется. Кинематика `sqrt(2s/4.5)` делает это честно: на 2 м поперёк линии защитник тратит 0.94 с, а не 0.53 с. **`speedK` из конфига удалить.**

### 3.3 Качество приёма Q

```
Q = q_speed · q_body · q_press · q_height · q_momentum
```

| Множитель | Формула | Откуда |
|---|---|---|
| `q_speed` | `clamp(1 − (v_приход − 8)/22, 0.45, 1.0)` | FC 26: сложность первого касания = f(скорость мяча). 8 м/с → 1.0, 20 м/с → 0.45 |
| `q_body` | `0.70 + 0.30·(1 + cos θ)/2` | коучинговый half-turn + FC 26: «первый пас под 135° и 180° существенно менее точен» |
| `q_press` | `1 − 0.35·clamp(1 − d_opp/R_press, 0, 1)` | Composure как ДВУХпараметрическая модель |
| `R_press` | `4.5 − 1.8·composure` м | «Composure определяет, с какой дистанции игрок начинает чувствовать давление» |
| `q_height` | земля 1.00 · настильный верх 0.86 · навес 0.78 | «lofted passes: players may take longer to control» |
| `q_momentum` | 1.15 если цель впереди адресата в конусе ±35° от его бега; 0.85 если пас в ноги бегущему | обычный пас: «получатель притормаживает, чтобы принять»; through ball: «бежит на мяч, не теряя скорости» |

### 3.4 Ценность продвижения — аналитический xT

Полная матрица 16×12 не нужна, берём замкнутую аппроксимацию (форма совпадает с картой Karun Singh, расхождение на глаз < 15 %):

```
T(p) = exp(−d_ворота / 18) · (0.35 + 0.65·cos λ)
```
`d_ворота` — метры до центра чужих ворот, `λ` — угол между направлением на ворота и осью поля.

| точка | T |
|---|---|
| точка пенальти (11 м по центру) | 0.54 |
| 16 м по центру | 0.41 |
| 16 м под углом 70° | 0.24 |
| 30 м по центру | 0.19 |
| центр поля | 0.06 |

```
ΔT = T(цель) − T(мяч)
V  = clamp(1 + 6·ΔT, 0.55, 3.0)
```
Пас назад (ΔT ≈ −0.03) даёт V = 0.82 — не запрещён, а дешевле. Это критично: в реальном футболе откат назад + «coming short» = **25.7 % всех рывков**.

**Множители семейств F — прямо из голов на 100 попыток (American Soccer Analysis, доставка в Zone 17):**

| Семейство | голов/100 | F |
|---|---|---|
| Пас за линию обороны | **13.2** | **2.2** (сырое 3.2 обрезано — AI исполняет с ошибкой) |
| **Cutback** | **6.4** | **1.6** |
| Прогрессивный пас | 4.5 | 1.1 |
| Обычный пас | 4.1 | 1.0 |
| **Навес в штрафную** | **2.5** | **0.6** |

### 3.5 Итоговая формула

```
S = P_complete^1.6 · Q · V · F · roleBias
```

- **Показатель 1.6 на безопасности — главный рычаг «не дешевеют ли голы».** При 1.6 пас с P = 0.70 теряет 46 % ценности против P = 0.95. Поднять до 2.2 — осторожное тики-така; опустить до 1.0 — аркада. [ОЦЕНКА, калибруется автосимуляцией по счёту 1:0–3:2.]
- `roleBias`: партнёру-вратарю **×0.7** (порт из gfootball: «don't like playing back to goalie»).

```
S_min = 0.55
под прессингом:  S_min ×= 0.60
кандидаты с S > S_min → softmax(S / 0.35), выбор случайный по распределению
```

Температура 0.35 даёт лучший вариант примерно в **65 %** случаев. Это одновременно (а) обязательный анти-предсказуемостный шум («optimal play is predictable play») и (б) реалистичная доля игнорируемых рывков: в реальности пасующий адресует лишь **26–35 %** забегов партнёров (SkillCorner; аномалия — Сен-Максимен, 60 %).

Никто не прошёл → ведение; и оно закрыто (соперник ближе 2.0 м по курсу) → панический вынос вперёд-в-сторону.

### 3.6 Ошибка исполнения

```
σ_angle = max(0.006, 0.020 · (1 − pass_skill) · k_press · k_body · k_first · k_family)   // рад
k_press  = 1 + 0.8·clamp(1 − d_opp/R_press, 0, 1)
k_body   = 1 + 0.6·(1 − cos φ)          // φ — доворот корпуса; 135–180° даёт 2.2
k_first  = 1.35 если пас первым касанием
k_family = земля 1.0 · верх 1.4 · на ход 1.2
σ_power  = 0.06 · (1 − pass_skill) · k_press          // доля силы
```

Пол `0.006` обязателен, иначе мастер = автомат.

**Скорость и точность — ОДИН атрибут** (так у EA: «Short Passing определяет точность И скорость паса»): `v0 ×= 0.85 + 0.15·pass_skill`. Плохой пасующий катит медленнее — и это второй, неявный канал наказания: медленный мяч легче перехватить по §3.2. Ту же схему явно ввела инди-игра GOALS: «скорости пасов теперь динамически масштабируются атрибутами пасующего».

**Разделить ground и air в атрибутах** (как у EA): Long Passing отвечает ТОЛЬКО за верховые длинные и «не влияет на длинные пасы по земле». Это позволяет Пирло отличаться от Джеррарда.

**Трёхслойная модель Football Manager — маппится 1:1 на нашу архитектуру «тренер → голова → ноги»:**
Vision = сколько кандидатов вообще попадает в список · Decisions = какой выбран · Passing/Technique = шум исполнения. Три стадии, три атрибута. Не схлопывать в один «pass rating».

## 4. Приём мяча

Плохая модель приёма убивает пас четырьмя способами, и все четыре надо закрыть.

1. **Потеря импульса.** Если приём обнуляет скорость, каждый пас — остановка атаки, и комбинация из трёх пасов проигрывает одному рывку. Лечение FC 26: «significantly improved responsiveness of first touch **to seamlessly transition into dribbling**».
2. **Разворот к пасующему.** Приём должен гасить мяч ПО ЕГО ходу под ноги (у нас это уже правило от 24.07.2026). Коучинговый эталон — приём **в полуоборот**: корпус раскрыт поперёк поля, можно играть в обе стороны.
3. **Нет окна паса в одно касание** → one-two физически невозможен. Нужна отдельная ветка first-touch анимаций паса.
4. **Нет буфера ввода.** Ввод паса, нажатый ДО контакта, обязан ставиться в очередь и исполняться в кадре касания.

**Числа приёма** (те же 10 875 пасов АПЛ): темп овладения `λ = 4.30 ± 0.28 с⁻¹` ⇒ **среднее время приёма 1/λ = 0.23 с**; игрок овладевает мячом с вероятностью **≈ 95 % в течение первой секунды**. Эти 0.23 с — искомое окно приёма для правила «касание только телом».

**Ошибка первого касания** — не плоский рандом, а функция: скорость мяча, высота, угол прихода, давление, часть тела, атрибут Ball Control. Плюс размен «контроль ценой скорости» (у EA — Precision First Touch на L2: чем раньше нажат ввод, тем больше контроль, но игрок встаёт).

**Множители эффективности по амплуа** (подгонка по трекингу, готовые числа для ролей):

| Амплуа | Приём адресованного | Перехват чужого |
|---|---|---|
| Защитник | 1.04 | **1.13** |
| Полузащитник | 1.23 | 0.57 |
| Нападающий | **1.36** | 0.23 |
| Вратарь | 0.80 | 0.48 |

Читается так: нападающий борется за свой мяч на 36 % активнее модели, но за чужой пас почти не борется.

**Разнообразие приёма встроено рандомом.** У Бакленда `ChanceOfUsingArriveTypeReceiveBehavior = 0.5`: половина приёмов — «встань и жди», половина — идти навстречу. Дешёвый источник вариативности.

## 5. Движение без мяча

### 5.1 Что считается рывком

Операционное определение SkillCorner/CIES, дословно: **период более 0.7 с, в течение которого игрок превышает 15 км/ч (4.17 м/с) И представляет собой опцию для паса** (с учётом взаимного положения и ориентации). Плюс важная оговорка, которую легко потерять: **забеги считаются только в фазах владения своей команды.**

```js
run.minSpeed   = 4.2   // м/с
run.minHold    = 0.9   // с, раньше не отменяем
run.optionGate = true  // рывок регистрируется, только если S(пас на него) > 0.30
```
Всё медленнее — это **позиционирование** (support spot), оно не тратит бюджет рывков. Это самая чистая граница состояний в автомате «головы».

Скоростные полосы SkillCorner поверх порога: **running < HSR (5.5–6.9 м/с) < sprint (> 6.94 м/с)**. Три уровня для стейт-машины.

### 5.2 Десять типов рывков: триггеры и цели

`X_off` — линия офсайда (§7), `C` — владелец мяча, атака в +x.

| # | Тип | Доля (CIES) | Триггер | Целевая точка |
|---|---|---|---|---|
| 1 | **Ahead of the ball** (вперёд, но не за линию) | 21.7 % | `C.vx > 1.5`, бегун впереди мяча и позади линии обороны | `x = min(C.x + 14, X_off − 2)`, своя вертикальная полоса |
| 2 | **Support** (поддержка) | 17.5 % | всегда ≥ 1 игрок (FC 26: «всегда иметь опцию для паса») | лучшая точка в кольце **12–16 м** от C, позади мяча ≥ 2 м. Бюджет не тратит |
| 3 | **Dropping off** (открыться назад) | 15.0 % | C в своей трети или под прессингом; роль CB/DM | 6 м к своим воротам + 8 м в сторону, обязательно ВНЕ линии `C → свои ворота` (иначе угол не открылся) |
| 4 | **Coming short** (показаться накоротке) | 10.7 % | C прессингуют (соперник < 3.0 м) И нет опции с `P_complete > 0.80` | точка на отрезке `C→бегун` в 8 м от C, сдвиг 2.5 м прочь от ближайшего соперника. Спринтом |
| 5 | **In behind** (за спину) | 10.5 % | C свободен, `d(C, ворота) < 45`, зазор «линия обороны ↔ вратарь» ≥ 12 м, бегун онсайд и не дальше 6 м от `X_off` | `x = X_off + 8`, `z` = середина между двумя ближайшими друг к другу защитниками. Первые 0.6 с держим `x = X_off − 0.5` — **дуговой забег**, чтобы не залезть в офсайд |
| 6 | **Cross receiver** (под подачу) | 9.2 % | партнёр в финальной трети, \|z\| > 19, готовит подачу | четыре разные точки четырём игрокам, см. ниже |
| 7 | **Lateral** (смещение в полосу) | 9.0 % | сосед занял мою полосу (конфликт ячеек §6) | центр соседней свободной полосы на своей глубине |
| 8 | **Over/underlap** (забегание) | 6.4 % | C в широкой полосе, фулбек в 22 м позади | оверлап: `x = C.x + 15`, `\|z\| = 31.5`; андерлап: тот же x, `\|z\| = 13` |
| 9 | **Third man** (третий игрок) | — | срабатывает на **ПЕРВОМ КАСАНИИ игрока B**, а не на выпуске паса A→B (пас ≤ 14 м, в ноги) | точка `B + 10 м` по направлению `A→B`, довёрнутому на 25–40° к воротам. Окно жизни 1.4 с |
| 10 | **Decoy** (обманный, увод опекуна) | — | только финальная треть, только при свободном слоте бюджета и низком собственном скоре | цель, максимизирующая свободное пространство ПАРТНЁРА после сдвига опекуна; опекун моделируется как следующий за бегуном с коэффициентом 0.8 за 1 с |

**Четыре точки под подачу** (зоны из FIFA Training Centre + ASA):
- ближняя штанга `(±47.0, ±2.5)` со стороны мяча
- «золотая зона» между вратарской и точкой пенальти `(±42.5, 0)`
- дальняя штанга `(±46.5, ∓5.0)`
- **трейлер под cutback `(±34.5, 0)`** — игрок у линии штрафной. Именно он даёт 6.4 гола на 100 против 2.5 у навеса. Без него cutback некому замыкать, и весь §8 не работает.

**Деталь, которой нет ни в одном открытом движке.** Ни gfootball, ни Simple Soccer, ни agent2d, ни CYRUS не моделируют обман: все оптимизируют «занять хорошее место», никто — «заставить защитника занять плохое». Тип №10 (decoy как рывок, чья полезность = прирост свободного пространства ПАРТНЁРА) — это ровно разница между PES и FIFA, и он дешёвый.

Коучинговые типы, не покрытые геометрической таксономией, но кодируемые:
- **Blindside run:** считаем конус зрения защитника на мяч; рывок «слепой», если бегун вне этого конуса. Формально: «стартовая позиция такая, где защитник не может видеть одновременно мяч и атакующего».
- **Double movement / check away:** двухфазный рывок — на касание партнёра форвард сначала уходит в противоположную сторону, потом показывается. У Football Manager это закодировано инструкцией Move Into Channels: «побежит в промежуток между защитниками, затем уйдёт в сторону, чтобы вытащить защитника из позиции».
- **Curved / arced run:** дуга не только держит онсайд, но и разворачивает корпус под приём — «уходя в мяч по дуге, игрок развернётся С мячом».

### 5.3 Бюджет рывков — здесь в исходных данных была ошибка в 5 раз

```js
runs.maxInSpace = 2   // in behind / ahead of ball / over-underlap / cross receiver / decoy
runs.maxToFeet  = 1   // coming short / dropping off
runs.maxTotal   = 3
runs.cooldown   = 6.0 // с на игрока
runs.duration   = { behind: 4.0, ahead: 2.5, short: 1.6, overlap: 3.5, cross: 2.0, third: 1.4 }
```

**Пересчёт бюджета.** 15.1 квалифицированного забега на игрока за 90 минут × 10 полевых = **~151 забег на команду за матч**, ~302 на обе. Это **один забег примерно каждые 11 с чистого игрового времени**, а не «каждые 2 секунды», как получается при делении на календарное время матча. На игрока — один забег в ~6 минут по часам, или примерно один в 2 минуты собственного владения. Если заложить «каждые 2 секунды», AI будет ломиться вперёд в 5–10 раз чаще реального футбола, и голы подешевеют.

**Обоснование пропорции 2:1.** Реальный сплит «в пространство / в ноги» = **72.2 / 27.8** (Serie A 69.3 — самая позиционная, Liga MX 74.9 — самая прямая; клубные крайности: Cercle Brugge 85.8 % в пространство, Burnley 39.3 % в ноги). 2:1 = 67/33. Один командный скаляр `inSpaceBias ∈ [0.6, 0.8]` воспроизводит идентичность лиги: 0.75 → `2/1`, 0.62 → `1/1` (позиционная игра).

Потолок 3 против 1 у gfootball выбран потому, что gfootball — обучающая среда, а не ТВ-картинка; CIES прямо отмечает, что support и ahead-of-ball «часто вовлекают нескольких игроков одновременно». Но 3 — предел читаемости кадра 320×240. [ОЦЕНКА.]

**Приоритет ролей при конкуренции за слот** (нормированные столбцы таблицы CIES «доля типа у позиции», max = 1.0) — готовая таблица для `data/`:

| | CB | FB | DM | AM | W | CF |
|---|---|---|---|---|---|---|
| in behind | 0.03 | 0.19 | 0.16 | 0.36 | 0.57 | **1.00** |
| ahead of ball | 0.24 | 0.78 | 0.64 | 0.89 | **1.00** | 0.76 |
| coming short | 0.31 | 0.13 | **1.00** | 0.48 | 0.29 | 0.27 |

Выбор типа: `argmax(rolePref[role][type] · situationGate[type])`.

**Ценность рывка (SkillCorner).** Каждому забегу присваивается xT — вероятность гола команды в течение 10 секунд, если игрока обслужат мячом. При xT ≥ **2 %** забег считается «опасным». **Две трети забегов за спину — опасные**; каждые 100 обслуженных забегов под подачу дают **≈ 7 голов** — вдвое больше, чем забеги за спину. Это второй, независимый аргумент за приоритет прострела.

### 5.4 Кто идёт назад (coming short)

```
score(p) = 1.6·(1 − d(p, C)/18)
         + 1.0·freeSpace(p)                    // safeDist 5 м
         + 0.8·rolePref[role]["coming short"]
         − 1.2·cellConflict(p)
         − 0.9·isLastManBehind(p)
```
`argmax`, гистерезис **0.15**, коммит **1.8 с**.

### 5.5 Коммитмент — обязательное правило

Три независимые реализации сошлись на одном: **per-frame argmax даёт дрожание**, и это ровно «modern FIFA feel», который концепт отвергает.
- Bakland: `SupportSpotUpdateFreq = 1` — точка поддержки пересчитывается **раз в секунду**, между пересчётами возвращается кэш. У нас — раз в 0.5 с.
- gfootball: рывок держится ровно **4000 мс**, и во время рывка **вес отталкивания от соперников падает вчетверо** (радиус с 5 м до 2 м) — бегун сознательно перестаёт обходить защитников, иначе рывок за спину вырождается в дугу вокруг всех.
- CYRUS: коммит к назначенному пасующему.

Рывок нельзя отменить первые **1.0 с**, кроме: офсайд / мяч потерян / пас ушёл другому.

## 6. Расстановка и разнесение

**Пять вертикальных полос** (поле 68 м):
```
центр      |z| ≤ 6.8
полуфланг  6.8 < |z| ≤ 20.4
фланг      20.4 < |z| ≤ 34
```
[Равные трети полуширины — ОЦЕНКА; доски Гвардиолы используют неравные полосы, точные ширины не опубликованы.]

**Жёсткие правила Juego de Posición** (подтверждены тремя независимыми источниками):
1. **≤ 2 атакующих в одной вертикальной полосе.**
2. **≤ 3 на одной горизонтальной ленте** (лента = 15 м по x).
3. **Запрет плоской пары:** если между партнёрами `|Δz| < 8 м` — обязателен `|Δx| ≥ 5 м`. Двигается тот, у кого ниже приоритет роли. Из этого правила треугольники и ромбы получаются САМИ, их не надо конструировать.
4. **Минимальная дистанция 4.5 м** в фазе атаки (не путать с физическим `separationRadius = 1.6`).
5. **Кольцо поддержки 12–16 м:** отталкивание при `d(C) < 9`, притяжение при `d(C) > 16`. Три традиции сошлись независимо: gfootball (притяжение с масштабом 21 м + отталкивание 12 м = равновесный аннулус 12–21 м), коучинг (10–15 м), Бакленд (оптимум 200 px). Крюйфф: максимум 10 м между линиями.

**Реализация — карта ячеек, не решатель.** Сетка **5 полос × 7 лент = 35 ячеек**, байт на ячейку, пересчёт на такте тренера (0.25 с). Целевая точка рывка ОТКЛОНЯЕТСЯ, если ячейка занята игроком с более высоким приоритетом. O(n), 22 проверки на такт.

**Прессинг — модель с числами** (закрывает дыру «Composure»):
- Радиус фиксации давления **4.57 м** (StatsBomb пишет событие Pressure в радиусе 5 ярдов); для вратаря и розыгрыша расширяется до **9.1 м**.
- **Порог активного прессинга 2.0 м/с** — защитник, движущийся медленнее, даёт НУЛЕВОЕ давление. Это убирает «толпу, которая давит стоя».
- Штраф за неправильную ориентацию: `τ_β = ‖u‖·β/π`, где β — угол между направлением на цель и вектором скорости.
- Известный дефект модели: она считает поле бесконечным, и прижатый к бровке игрок числится свободным. **У нас бровка обязана работать как двенадцатый защитник.**

**Кинематика игрока — разрешение противоречия.** В литературе фигурируют максимальные скорости 5.0 / 8.0 / 9.2 / 13.0 м/с — это РАЗНЫЕ величины, а не разногласие: 5.0 — жёсткий потолок в чужом коде, 9.2 — кинематический максимум спринта, **13.0 — асимптотический параметр модели `Vmax = F/k`, недостижимый в принципе**. В `CONFIG` нужны раздельно `sprintSpeed` (реальный потолок), `alpha` (обратная постоянная разгона, 1.04–1.23 с⁻¹) и производный **радиус достижимости: 6.16 м за 1 с и 12.94 м за 2 с** — именно он нужен для решений о подкате и перехвате. Реальное распределение скоростей полевых: пик на **1 м/с (шаг)** и второй на **3 м/с (трусца)** — большинство игроков не бежит.

```
для каждого соперника:  x_j = pos.x + vel.x · 0.24     // экстраполяция 240 мс
X_off = ВТОРОЙ по глубине x_j                          // ассоциативный футбол, не первый
X_off = max(X_off, ball.x)
X_off = min(X_off, 0)                                  // никогда не за середину поля
запас = 0.08 м
```
Бегущий за спину держится на `X_off − 0.3` до момента **выпуска мяча**, затем свободен. Экстраполяция обязательна: мгновенная линия даёт офсайды-фантомы на отходящей защите.

## 8. Комбинации

**Стенка (give-and-go / wall pass).** Ввод-эталон: PES 6 — держать R1 рядом с партнёром и вернуть мяч кнопкой X; FIFA — держать L1 всю связку, отпустил → комбинация не сработала. Пасующий автоматически уходит в рывок. Практическое замечание из туториала, прямо применимое к AI: **one-two без встречного движения третьего игрока бесполезен** — получается линейный пинг-понг.

**Третий игрок (third-man run) — самая ценная комбинация для реализации.** Формально: «игрок, получающий последний решающий пас, — НЕ тот, на кого пасующий смотрел первым». Механизм: A ведёт и притягивает прессующего → B принимает между линий (часто спиной к воротам) → C выходит в зону, которую освободил опекун игрока A. Превращает 2v2 в позиционное превосходство и достигает позиции, «которую нельзя найти прямым пасом».
**Ключевая деталь реализации:** триггер C — **первое касание B**, а не выпуск паса A→B. Требуется всего два элемента: (а) скидка/стенка, (б) отложенный третий бегун.
Варианты: прямой угловой (игроки на разной высоте), **блайндсайд** (B уходит в слепую зону, чтобы найти C), **перевёрнутый треугольник** (один опорный + двое за спиной прессующего = две опции сразу).

**Забегание.** Оверлап — старт позади владельца, финиш впереди и СНАРУЖИ; андерлап — впереди и ВНУТРИ. Обе версии геометрически определены и в трекинге, и в коучинге одинаково — редкий случай полного совпадения.

**Ротация** (вингер внутрь + фулбек снаружи) — это механическая композиция «pulling half space» + «overlap», выполненная одновременно. У FC 26 закодирована ролями (Inverted Wingback уходит в центр и высоко).

**Что делать против низкого блока** (проверенный рецепт, прямо описывающий поведение нашего AI): растянуть фланг и угрожать прострелом → откатить мяч назад на фулбека или оттянутого полузащитника → пас в центр, в зону, освобождённую сместившимся опорником; плюс третий игрок. Дриблинг в толпе не работает; работают быстрые пасовые связки, потому что AI-защитники не успевают мгновенно закрыть освободившуюся зону.

**Как игрок вручную создаёт опцию** (для нашей схемы управления): PES-подход правильнее FIFA-шного. В PES/eFootball правый стик выбирает партнёра, а **отпускание стика отправляет его в рывок в последнем заданном направлении** — «задать курс и отпустить», а не выбрать пункт меню. У FIFA это разбито на L1 = рывок за спину, R1 = показаться накоротке, дальше флик правым стиком рулит бегуном на 360°. Для нас ближе PES-схема: одна кнопка + направление.

## 9. Почему прострел — главное оружие

**Числа (American Soccer Analysis, трекинг MLS):**
- **82 % голов** — из ударов в Zone 17 (центральная зона штрафной).
- Голов на 100 попыток доставки в Zone 17: пас за линию **13.2**, **cutback 6.4**, прогрессивный пас 4.5, обычный пас 4.1, **навес ≈ 2.5** (один гол на ~40 подач).
- Cutback: **1.56 попытки за матч, точность 32 %, 25 % удавшихся превращаются в удар.**
- **97 % ударов после cutback** попадают в тиры Great/Good/Average по xG, **99 % голов**. То есть прострел почти не порождает «мусорных» ударов.
- Темп решает: у прострела **59 % голов приходит на быструю игру** — медленный cutback чаще блокируют.
- Кросс, независимая проверка: точность с игры **20.5–20.8 %** (со стандартов 33.9 %), **~79 кроссов с игры на гол**, кроссы с игры дают ~15 % всех голов. Элита: Александер-Арнолд 23 % при 297 подачах за сезон — то есть **лучший в мире едва выше среднего.**

Сводим: **прострел в 1.5 раза чаще доходит и в 2.5 раза чаще приводит к голу, чем навес.**

**Почему это работает механически** (три уязвимости, все три моделируемы):
1. Вратарь **не видит мяч** или пойман в момент смещения поперёк ворот — подача идёт от линии ворот, ему приходится решать и двигаться одновременно.
2. Защитники **лицом к своим воротам**, дезорганизованы, выбивать тяжело.
3. **Опоздавшие набегающие свободны** — защитники смотрят на ворота и не видят игроков за спиной.
Целевая зона — между вратарской и точкой пенальти.

**Вывод для геймплея.** Прострел должен быть отдельным семейством паса с F = 1.6, отдельной зоной активации (x в 9 м от лицевой, |z| > 7), отдельной целевой точкой (золотая зона) и **обязательным трейлером** у линии штрафной. В ретро-схеме ввода это третий тап кнопки навеса — ровно как в PES 6 (□ ×1 навес на дальнюю, ×2 настильный на ближнюю, ×3 низкий прострел). Одна кнопка, три уровня высоты — идеально совместимо с эстетикой конца 90-х.

Навес при этом обязан быть **невыгодным по умолчанию** (F = 0.6). Он нужен как запасной вариант при закрытом коридоре, а не как основное оружие — иначе получаем FIFA-мету «навал с флангов».

## 11. Что берём в проект

1. **Переписать силу паса на `v0 = arrive + 0.724·d`**, `arrive` = 6 / 9 / 13. Без этого весь остальной документ бесполезен: пас медленнее спринта. `passSpeedMin/Max` → 12 / 30.
2. **Перехват — по времени, а не по коридору.** Логистика с `σ = 0.45 с` (коэффициент 4.03), реакция 0.35 с, разгон 4.5 м/с². **Удалить `passIntercept.speedK`** — кинематика делает его работу честно.
3. **Формула выбора паса `S = P^1.6 · Q · V · F · roleBias`**, порог 0.55 (×0.60 под прессингом), выбор через softmax с температурой 0.35 (лучший вариант в 65 % случаев). Показатель 1.6 — главная ручка «не дешевеют ли голы».
4. **Пять кандидатов на партнёра**, включая две касательные к кругу перехвата (коэффициент 0.30) и точку в зазоре между соперниками.
5. **xT замкнутой формулой** `exp(−d/18)·(0.35 + 0.65·cos λ)` — без матрицы 16×12.
6. **Семейства паса с F-множителями из голов на 100 попыток:** за линию 2.2, **cutback 1.6**, навес **0.6**. Прострел — отдельный тип с зоной активации и обязательным трейлером у линии штрафной; ввод — третий тап кнопки навеса, как в PES 6.
7. **Ошибка = атрибут × давление × разворот корпуса × первое касание × семейство.** Composure двухпараметрический: радиус `4.5 − 1.8·composure` м И множитель ошибки внутри него. Скорость и точность — один атрибут; земля и воздух — разные атрибуты.
8. **Трейты как `{семейство, шкала, величина}`**, где шкала ∈ {точность, скорость, подкрутка, перехватываемость, сложность приёма}. Никогда не «+10 к пасу». И трейт — смещение поверх непрерывных атрибутов, а не переключатель способности (к этому EA пришла за три года).
9. **Ассист — число `0.0…1.0`, три независимые коррекции** (выбор адресата / расчёт силы / обход соперников), а не один флаг. Плюс асимметрия PES: ассистированный пас проверяется на автоперехват, ручной — нет.
10. **Приём: окно 0.23 с, 95 % за первую секунду**, множители по амплуа (нападающий 1.36 на своём мяче / 0.23 на чужом), сохранение импульса, приём в полуоборот, буфер ввода для паса в одно касание.
11. **Рывок = > 0.7 с при > 4.17 м/с И быть опцией для паса.** Бюджет: `maxInSpace 2 / maxToFeet 1 / maxTotal 3`, кулдаун 6 с, длительность 1.4–4.0 с по типу. **~151 рывок на команду за матч, один примерно в 11 с чистого владения** — не в 2 с.
12. **Таблица `rolePref[role][runType]`** (нормированные доли CIES) — в `data/`, не в коде. Плюс командный скаляр `inSpaceBias 0.6–0.8`, воспроизводящий стиль лиги одним числом.
13. **Третий игрок с триггером на первом касании B** — самая ценная комбинация, стоит двух элементов.
14. **Decoy-рывок, чья полезность = прирост свободного пространства ПАРТНЁРА.** Этого нет ни в одном открытом движке; это и есть PES против FIFA.
15. **Карта ячеек 5 × 7, правила ≤2 в полосе / ≤3 на ленте / запрет плоской пары / кольцо 12–16 м.** Треугольники получаются сами.
16. **Офсайд — по ВТОРОМУ защитнику с экстраполяцией 240 мс**, `max(ball.x)`, никогда за середину поля.
17. **Коммитмент:** support spot раз в 0.5 с из кэша, рывок неотменяем 1.0 с, во время рывка вес обхода соперников ×0.4.
18. **Прессинг:** радиус 4.57 м (вратарь 9.1), порог активности 2.0 м/с, штраф за ориентацию, та же `σ = 0.45`. Бровка обязана давить.
19. **Любая правка веса паса — тем же коммитом, что и ретюн риск-модели AI.** Иначе AI перестанет играть вперёд.
